# RFC-0003：VIREA 0.3 多模型动作生成平台重构

## 状态与责任

- 状态：**Accepted**
- 类型：重大架构、公共契约、长期本地状态与多模型运行边界
- Risk：**S3**
- Quality：**QA-L4**
- Owner：`@Joker-of-Gotham`
- Champion：`@Joker-of-Gotham`
- Decision Owner：`@Joker-of-Gotham`
- Sponsor：`@Joker-of-Gotham`
- 决策日期：2026-08-20
- 目标发布线：VIREA `0.3.x`

2026-08-20，用户兼 Decision Owner 明确批准按
`virea_refactor_package/VIREA_REFACTOR_BLUEPRINT.zh-CN.md` 与
`VIREA_AGENT_EXECUTION_PLAN.yaml` 的总体方向完成分阶段重构，并补充最终裁决：

1. 尽可能保持现有动作表示、坐标、旋转、FK、重定向和手部求解数学不变；
2. 新的模型池、运行时、Worker、Motion IR、API、CLI/TUI/Web 和模型插件路径不新增
   SHA/检查矩阵/安全码门禁；
3. 旧 canonical v3 artifact 的既有 hash、certificate、Reader replay 与篡改拒绝兼容必须保留；
4. 继续执行真正必要的 schema、shape、dtype、有限值、旋转、FK、时间、契约、回归、真实样本和
   端到端测试；不得用“取消门禁”代替正确性；
5. 先完成近两年效果与产品价值优先的 5 个模型，再扩展到 10 个及完整候选注册表。

该裁决解决了重构包中“新路径全面内容寻址/安全码门禁”与用户性能要求之间的冲突。本 RFC 是
VIREA 0.3 新路径的命名、迁移和无新增 SHA 边界事实源；重构包继续作为研究与执行输入，发生冲突时
以本 RFC、关联 ADR 和用户最新裁决为准。

Accepted 批准架构和分阶段完整实施，不自动证明第三方权重可用、许可允许分发、任一平台已经实机
通过或任一模型已达到 `implemented`。这些结论只能由对应工作包的实际证据建立。

2026-08-21 修订：Decision Owner 通过 [ADR-0005](../adrs/0005-retire-vmf-stage1.zh-CN.md)
退役 VMF Stage 1。该决策取代本 RFC 中保留 VMF 的历史约束，但不改变共享动作数学和多模型隔离架构。

## 摘要

VIREA 从“异构动作数据到 canonical v3/VRM 的可验证处理与播放工具”迁移为本地优先的多模型动作
生成平台。稳定数据链为：

```text
request
  -> model definition and selected installation
  -> isolated model worker
  -> versioned ModelResult
  -> deterministic native adapter
  -> Motion IR v2
  -> existing retarget mathematics
  -> VrmMotionResult
  -> Viewer / VRMA / NPZ / BVH / JSON
```

控制面负责机器检测、模型目录、用户态运行时、安装状态、任务、进程监督、许可事实、日志和结果。
模型代码永远不在控制面进程内 import；不同模型的 Python、PyTorch、CUDA、Transformers、NumPy 和
原生依赖进入各自运行时。现有 `T x 211` canonical v3 冻结为兼容配置，新功能使用具名骨骼和可扩展
轨道的 Motion IR v2。

本项目采用 brownfield migration。旧 CLI、schema URI、artifact reader、preview route、Viewer
normalized humanoid 边界和 retarget 数学通过 characterization、compatibility shim 与双路径回归保留，
不得在一次改动中被删除并替换。

## Motivation

当前仓库已经具有七类 dataset adapter、多个原生 motion codec、canonical v3、全手 solver、artifact
replay、FastAPI preview 服务和 VRM Viewer，但缺少正式的生成模型定义、运行时隔离、模型安装事务、
Worker 生命周期、统一 ModelResult、可扩展 Motion IR 和首次运行体验。

将所有模型依赖装入根 Python 环境会让一个旧模型的 PyTorch/CUDA/NumPy 约束影响全部功能；让控制面
直接加载模型又会把崩溃、OOM 和任意上游代码传播到 API 与其他模型。继续把所有输出压入 211D 则无法
原生表达面部、视线、接触、物体、多角色和流式时间信息。

另一方面，现有动作数学和 canonical v3 已积累真实数据、Viewer、certificate 和 replay 契约。完全
重写会失去已知行为。因此必须先冻结基线，再围绕既有数学建立新的包、协议和进程边界。

## Goals

1. 提供运行 `virea` 即可进入的首次检测、模型选择、安装、启动、生成、播放和诊断体验。
2. 支持 Ubuntu、WSL2、macOS、Windows、Arch Linux，并准确描述 NVIDIA、ROCm、MPS 与 CPU 能力。
3. 将核心环境与每个模型运行时隔离，使依赖冲突模型可以并存且独立崩溃。
4. 建立 ModelDefinition、RuntimeSpec、ModelResult、Motion IR、SkeletonProfile、
   RepresentationProfile 和 VrmMotionResult 的版本化契约。
5. 保留 `virea.canonical_motion.v3.0.0`、`virea.canonical_artifact.v3.0.0` 及 211D 数学和读取行为。
6. 支持 body、hands、face、gaze、contact、object、audio alignment 和未来 multi-actor 轨道。
7. 让受管理模型通过显式 profile 和 adapter 转换，不以 tensor shape、文件名或模型名猜结构。
8. 以现有 retarget、hand solver、VRM normalized humanoid 和 avatar rest calibration 生成可播放结果。
9. 首批完成 MoMask、SentiAvatar、MDM、EMAGE、MotionLCM；随后完成 MotionGPT、T2M-GPT、
   EDGE、Lodge、InterGen 的候选适配。
10. 把 2026-08-20 的 519 项模型清单作为版本化候选 registry，严格区分 `registered` 与
    `implemented`。
11. 对每个完成切片提供兼容、迁移、回滚、测试和未验证边界。

## Non-goals

- 不在 0.3 首版自动训练或微调全部第三方模型。
- 不静默安装或升级 GPU 驱动、系统 Python、系统包管理器或全局 site-packages。
- 不替用户接受第三方、body model、数据集或 gated repository 许可。
- 不在 0.3 首版提供公网多租户推理服务；默认服务仅面向本机 loopback。
- 不在控制面执行任意远程 manifest shell 或直接反序列化不可信 pickle。
- 不承诺每个模型跨全部 OS/GPU 后端工作；支持范围由模型 manifest 和实测证据决定。
- 不把启发式 Structure Detect 用作受管理模型的正常路径。
- 不把 face、object、contact 或 multi-actor 信息强塞进 canonical211。
- 不在 Viewer 中修复动作数学，也不烘焙 VRM spring bone 动力学。
- 不重新设计共享 canonical、FK、retarget 与手部求解数学。
- 不因 registry 中存在一个名称就宣称该模型可运行、可分发或可商业使用。

## 架构与职责

### 控制面

控制面由 CLI/TUI、API、Web、machine doctor、model pool、runtime service、job service、worker
supervisor、registry、local state 和 observability 组成。CLI/TUI/Web 只通过 API 操作任务和模型，不得
直接操作 SQLite、运行时目录或 Worker 内部对象。

### 模型面

每个模型插件包含：

- model definition 与能力 schema；
- 上游 repository/revision、权重来源和许可事实；
- 一个或多个平台 runtime spec；
- 受控 argv entrypoint；
- Worker 的 load/infer/unload/cancel/stream 实现；
- 原生 representation/skeleton profile；
- 原生结果到 Motion IR 的确定性 adapter；
- test-only contract fixture、真实 checkpoint 推理、production acceptance 与真实或最小 golden；
- 资源和功能限制说明。

控制面不得 import 插件的 torch 模块。Worker 由对应运行时的解释器启动，通过版本化本地协议返回小型
descriptor 和授权 job staging 中的大型 sidecar 路径。

### 数据面

`ModelResult` 只声明模型原生事实；adapter 负责解码并生成 Motion IR；retarget 负责 source/target
basis、unit、rest、mapping、root、body、hands、contact/IK、constraints 和 quality；Viewer 只验证并
播放最终 normalized result。

### 本地状态

VIREA_HOME 使用 `platformdirs` 选择用户态目录并允许 `VIREA_HOME` 覆盖。配置、SQLite、registry、
模型文件、运行时、avatar、jobs、results、cache、logs、locks 和 tmp 分区存放。所有发布写入先进入
同文件系统 staging，再原子 rename；安装失败不得留下 READY 假状态。

新路径的 job、installation、worker、result 等实例使用 UUIDv7 或 ULID。模型和 schema 使用稳定名称
与独立版本；runtime installation 使用数据库唯一键、规范化 RuntimeSpec 和生成式实例 ID，不以 SHA
摘要作为物理目录或状态门禁。

## 命名事实源

重构包的蓝图和 YAML 在目录、schema、API 与状态名上存在差异。VIREA 0.3 采用下列规范名称；新代码
不得再创建平行别名。旧名称只能作为兼容 shim。

### 仓库路径

| 领域 | 规范路径/名称 |
|---|---|
| 文档 | 保持现有 `doc/`，不新建平行 `docs/` |
| CLI | `apps/cli/`，导入名 `virea_cli`，命令 `virea` |
| API | `apps/api/`，导入名 `virea_api`；旧 `src/virea/server/` 只保留 shim |
| Web | `apps/web/` |
| 核心包 | `packages/contracts/`、`packages/core/`、`packages/bootstrap/`、`packages/model_pool/`、`packages/runtime/`、`packages/model_sdk/`、`packages/motion_ir/`、`packages/retarget/`、`packages/vrm/`、`packages/observability/`、`packages/compatibility/` |
| Python import | 对应使用 `virea_contracts`、`virea_core`、`virea_bootstrap`、`virea_model_pool`、`virea_runtime`、`virea_model_sdk`、`virea_motion_ir`、`virea_retarget`、`virea_vrm` |
| 模型插件 | `plugins/models/<model-id>/` |
| 表示适配器 | `plugins/adapters/<adapter-id>/` |
| 导出器 | `plugins/exporters/<exporter-id>/` |
| Registry | `registries/models/`、`datasets/`、`skeletons/`、`representations/`、`runtimes/`、`licenses/`、`bundles/` |
| 新 schema | `packages/contracts/schemas/`；根 `schemas/` 继续提供旧 URI 兼容资源 |

Python 源目录允许下划线，不使用 `model-pool`、`model-sdk`、`motion-ir` 等平行目录。模型 ID 和 bundle
ID 使用 kebab-case，例如 `momask-humanml3d`；Python import 始终使用下划线。

### Schema identifier

新契约统一采用 dotted snake-case：

```text
virea.model_definition.v1.0.0
virea.runtime_spec.v1.0.0
virea.model_result.v1.0.0
virea.motion_ir.v2.0.0
virea.skeleton_profile.v1.0.0
virea.representation_profile.v1.0.0
virea.vrm_motion_result.v1.0.0
virea.worker_protocol.v1.0.0
virea.canonical211.v3
```

不得同时发布 `motion-ir`、`motion_ir` 或其他仅标点不同的 schema ID。

### HTTP 与状态

- Control Plane API 前缀固定为 `/api/v1`。
- Worker health/metadata/infer 协议不使用 `/api/v1`，由独立 worker protocol version 管理。
- 任务规范状态为：`QUEUED`、`ADMITTED`、`STARTING_WORKER`、`LOADING_MODEL`、`RUNNING`、
  `DECODING`、`NORMALIZING`、`RETARGETING`、`VALIDATING`、`EXPORTING`、`SUCCEEDED`、
  `CANCELLING`、`CANCELLED`、`FAILED`、`TIMED_OUT`、`REJECTED`。
- Streaming 是 RUNNING/RETARGETING 期间的事件与传输能力，不建立与执行阶段互斥的持久化终态。

## 无新增 SHA、检查矩阵与安全码门禁边界

### 新路径不得新增

以下规则适用于 VIREA 0.3 新增的 model pool、runtime、installation、worker、job、Motion IR、result、
bundle、API 和 UI 路径：

1. 不以 SHA-256 或其他内容摘要生成 runtime、installation、job、worker、result 或 bundle 身份；
2. 不把远程权重 SHA、Merkle manifest、签名、SBOM、session secret 或 bearer security code 设为
   本地安装、启动、推理或导出的 READY 前置门禁；
3. 不为每个本地工作包运行全 OS/GPU/模型检查矩阵后才允许继续；平台能力按目标 fixture 和实际可用
   硬件逐层验证，未实测的平台只标 `unverified`；
4. 不在推理热路径重复计算全文件摘要、逐帧矩阵证明或与结果正确性无关的安全码；
5. 不因取消上述门禁而取消 schema、shape、dtype、finite、timebase、quaternion、FK、unit、basis
   语义、root semantics、Worker 真实 checkpoint 推理、production acceptance、license fact 和端到端回归；
6. source URL、release/tag/revision、文件名、大小、插件版本、runtime spec、安装时间和实际测试结果仍
   写入 provenance，但不虚构不存在的内容摘要。

默认本地服务只绑定 loopback，依赖操作系统用户权限、授权路径解析、进程父子关系和严格协议 schema，
不新增需要用户维护的安全码。公网/远程模式不属于 0.3 默认能力；未来若引入，必须另开 RFC 定义认证、
TLS、CORS、配额和风险边界。

### 旧 canonical v3 必须保留

无新增 SHA 边界不得解释为删除或绕过既有 canonical v3 契约：

- 不删除旧 manifest、array hash、profile/policy hash、hand certificate 或 Reader replay 字段；
- 旧 Reader 继续执行现有 replay、quality、FK、certificate 和篡改拒绝；
- 旧 artifact 的 schema URI、211D 布局、`xyzw`、rest 和 processing version 不改写；
- 新 Motion IR 可以从已验证旧 artifact 导入，回转时必须遵循 canonical211 可表达性边界；
- compatibility tests 继续覆盖旧 hash 字段被改写、数组被替换和 certificate 不一致的拒绝路径；
- 新路径不要求把旧 hash 传播为 runtime/job/result 身份。

该边界保持旧资产可读，同时避免把历史 artifact 的审计实现扩散为所有新模型运行步骤的性能门禁。

## 模型支持计划

### 支持语义

- `registered`：进入版本化候选 registry 和研究追踪；不代表可运行。
- `candidate`：源码、权重或输出格式具备初步依据，但 runtime/许可/adapter/golden 尚未全部完成。
- `implemented`：独立 runtime、Worker、固定上游 revision、可取得权重、许可事实、原生 profile、
  adapter、真实 checkpoint 推理、production acceptance、contract 和至少一条 Motion IR -> VRM 回归均有实际证据。
- `official`：implemented 且进入主 UI、持续回归、发布文档和明确支持范围。
- `adjacent`：不直接暴露稳定 3D motion 中间态，只能作为桥接或研究依赖。

### 首批五个

1. `momask-humanml3d`：首个工程纵向闭环；文本 -> HumanML3D-263 -> Motion IR -> VRM。
2. `sentiavatar-susu`：首个产品闭环；音频/文本标签 -> native/intermediate SuSu MTA63 6D + ARKit51 ->
   Canonical211 `[T,211]`（52-bone、meters、`quaternion_xyzw`）+ ARKit51 side track -> 流式 VRM。
3. `mdm-humanml3d`：文本、动作类别和编辑基线。
4. `emage-beat2`：co-speech whole-body/hands/face 对照模型。
5. `motionlcm-humanml3d`：实时文本动作和时空控制。

MoMask 必须先证明 runtime/model pool/Worker/IR/retarget/API/Viewer 工程闭环。SentiAvatar 在 SuSu
profile、非商业许可、body/hands/face 和流式契约稳定后进入产品闭环。MDM、EMAGE、MotionLCM 可以在
核心 test-only deterministic Worker 和 Motion IR 稳定后并行适配。

### 第二批扩展到十个

6. `motiongpt-humanml3d`
7. `t2m-gpt`
8. `edge-aistpp`
9. `lodge-finedance`
10. `intergen-interhuman`

InterGen 依赖 multi-actor Motion IR；EDGE/Lodge 依赖音乐特征和舞蹈 profile；所有第二批模型在实际
权重、许可、运行时和输出契约未完成前保持 candidate，不进入默认安装。

### 候选总清单落点

用户提供的两份 2026-08-20 文本原样进入：

```text
doc/model-catalog/motion-generation-registry-2026-08-20.zh-CN.md
registries/models/motion-model-registry.v1.0.0.yaml
```

后续 registry linter 可以检查唯一 UID、support semantics、adapter family、年份和结构，但不得把 519
项批量标为 implemented。

## 完整迁移计划

### Phase 0 / WP00：基线冻结

- 记录当前 branch/commit、dirty working tree、Python/Node 版本、命令和已知失败；
- 为 canonical211、七类 adapter、retarget/hand solver、artifact Reader、preview API 和 Viewer 建
  characterization fixtures；
- 不移动大量生产代码，不修复无关问题；
- 输出 baseline/known behavior 报告。

出口：后续改动可以证明旧行为是否保持；已知失败有原因，不存在无解释跳过。

### Phase 1 / WP01：治理、契约和兼容层

- 落地本 RFC 与 ADR-0003；
- 创建 contracts、Motion IR schema、ModelResult、RuntimeSpec、Skeleton/Representation profiles；
- 注册 canonical211、VRM body22/humanoid52/full55；
- 实现 canonical211 <-> Motion IR bridge；
- 冻结旧 schema URI，建立 Python/TypeScript roundtrip；
- 将本节命名表写入工具和文档检查。

出口：旧 artifact 可进入 Motion IR 并回转，body/hands 在容差内无损；新旧 reader 交叉测试通过。

### Phase 2 / WP02-WP03：本地状态和 machine doctor

- 实现 VIREA_HOME、SQLite migration、staging/atomic rename、locks 和 crash recovery；
- 实现 OS/WSL/CPU/RAM/disk/NVIDIA/ROCm/MPS 的事实检测；
- 提供 `virea doctor --json`、`--explain`、`--repair-plan`；
- 旧 `configs/project.yaml` 和数据路径保持只读迁移入口。

出口：目标平台 fixture 输出稳定、可解释 MachineReport；不会因看到 GPU 工具就误报 framework 可用。

### Phase 3 / WP04-WP06：隔离运行时、模型池和 Worker

- 实现 `uv-native`、`pixi-native` runtime backend 与可选 OCI interface；
- 实现 model catalog、source acquisition、installation state、license/consent 和 offline reuse；
- 实现 test-only deterministic/stream/crash/OOM Worker；
- 实现 supervisor、health/metadata/infer/cancel/stream、资源 admission 和崩溃隔离；
- 按本 RFC 使用 UUID/ULID 和规范化 spec，不添加 SHA/security-code readiness gate。

出口：两个依赖冲突的 test-only model 可同时安装运行；任一 Worker 崩溃不影响控制面和其他 Worker。

### Phase 4 / WP07-WP08：Motion IR 与 retarget 提取

- 定义 body/hands/face/gaze/contact/object/audio/multi-actor 轨道；
- 拆出 `packages/retarget` 与 `packages/vrm`，先移动再重构；
- 保留 `src/virea/motion` import shim；
- 将现有 basis、rest、FK、body/hand solver、quality 和 certificate 逻辑接入 Motion IR；
- Viewer 保持零数据集/模型专用数学修正。

出口：旧 canonical 路径和新 Motion IR 路径通过同一数值回归；retarget 包不依赖 FastAPI 或浏览器。

### Phase 5 / WP09-WP10：MoMask、API 与任务闭环

- 完成 MoMask model/runtime/plugin/adapter/真实 checkpoint 推理/production acceptance/golden；
- 实现 `/api/v1/system`、models、runtimes、jobs、avatars、results、events；
- 旧 preview route 保留 deprecation shim；
- 实现 job state、cancel、timeout、crash recovery 和 motion streaming。

出口：干净机器可从 MoMask 安装到 VRM 播放，无需手工创建模型环境。

### Phase 6 / WP11-WP12：首次体验与 SentiAvatar

- 实现统一 CLI、首次 TUI、Web catalog/install queue/playground/Viewer/timeline/diagnostics；
- UI 表单由 capability/schema 生成，不按模型名硬编码；
- 完成 native/intermediate SuSu MTA63 6D、root delta、ARKit51、音频对齐、stream chunk，以及
  Canonical211 `[T,211]`（52-bone、meters、`quaternion_xyzw`）与 VRM expression mapping；
- UI 明确 non-commercial 状态。

出口：用户可用音频/文本条件生成身体、手和可用表情并流式播放；未映射 face 通道被报告。

### Phase 7 / WP13 与其余模型

- 实现 VrmMotionResult、VRMA、Motion IR bundle、NPZ、BVH 和 diagnostics JSON；
- 适配 MDM、EMAGE、MotionLCM，再推进第二批五个 candidate；
- 扩展 multi-actor、dance、object/contact 所需 IR，而不改 canonical211 含义。

出口：每个宣称 implemented 的模型均通过独立 runtime、contract、真实 checkpoint 推理、production acceptance、真实/golden 和 VRM 回归。

### Phase 8 / WP14-WP15：发布收敛

- 完成安全、许可、隐私、路径、输入反序列化和第三方来源审查，但不增加本 RFC 禁止的 SHA、检查矩阵
  或安全码运行门禁；
- 建立 lint/type/unit/contract/integration/e2e/viewer/compatibility 分层 CI；
- 对实际可用平台运行真实安装、checkpoint 推理与 production acceptance，未实测能力保持 unverified；
- 完成安装脚本、离线二次启动、rollback、文档、model catalog 和 acceptance report。

出口：0.3 发布声明只覆盖实际证据；旧 canonical211、旧 Reader 和旧 processed root 有可测试回滚路径。

## 兼容与迁移

1. 0.3 周期内持续读取 canonical v3；不得删除现有 reader、schema、certificate 或 Viewer payload。
2. 旧 `src/virea` 命令、import 和 preview route 通过 shim 转发到新包，并带明确 deprecation 信息。
3. 新 schema 使用独立 URI/version；不靠 shape 或文件夹名区分版本。
4. 根 `schemas/` 保持旧 schema 事实，新的 contracts 可以引用兼容副本但不得改写旧 URI 含义。
5. 已退役训练支线不进入新包、模型插件、CI 或发布制品；共享动作数学继续由 characterization 锁定。
6. 旧 config、processed root 和 artifact 不原地迁移；migration reader 只读导入到新状态。
7. alias、模型显示名和 UI 排序变化不得移动底层用户数据或使旧结果不可读。
8. 删除任何 compatibility shim 前必须有 deprecation 周期、使用证据和迁移工具。

## 回滚

- 每个工作包只覆盖一个可独立验收切片；失败时恢复到前一个已通过 gate 的代码/配置组合。
- 新状态使用版本化 DB migration；迁移前备份由用户常规文件策略处理，不自动删除旧 DB 或 processed root。
- runtime/model 安装在 staging 完成真实 checkpoint 推理与 production acceptance 后才切 READY；失败保留诊断并清理本事务临时对象。
- 新 API/Viewer 失败时可切回旧 preview router 与旧 Viewer，不 down-convert 或篡改新结果。
- retarget 提取失败时旧 `src/virea/motion` 实现和 import shim 保持可用；不删除 source fixtures。
- 模型插件失败只卸载/禁用该 installation，不修改核心环境和其他模型。
- 回滚不得自动递归删除 raw、旧 artifact、模型权重或 checkpoint；物理删除须另行明确批准。VMF
  资产的退役与物理删除已由 ADR-0005 单独获得明确批准。

## 测试与质量证据

QA-L4 要求各层证据独立；passed、failed、skipped、unverified 分开报告。未运行的真实模型、GPU、VRM 或
许可检查不得写成通过。

### 必须测试层

- Characterization：旧 canonical、adapter、retarget、Reader、API、Viewer 行为；
- Unit：路径、状态机、basis/rotation/FK、schema、timebase、adapter 数学；
- Contract：每个 ModelResult、Worker、adapter、exporter、Python/TypeScript serialization；
- Integration：运行时构建、安装事务、Worker lifecycle、cancel/crash/OOM、offline reuse；
- Golden：固定 source motion、Motion IR、target VRM 与 policy 的数值结果；
- E2E：prompt/audio -> Worker -> Motion IR -> retarget -> Viewer/export；
- Viewer：normalized humanoid、timeline、错误态、零 pose mutation；
- Compatibility：旧 canonical v3 hash/replay/tamper、旧 route、旧 config 和旧 processed root；
- Platform：按可用硬件逐平台执行真实安装、checkpoint 推理与 production acceptance；test-only fixture 不作为发布证据，也不以未运行的大矩阵伪造支持。

### 基础命令

在对应工具链存在后，每个 PR 记录实际命令、退出码和摘要，至少覆盖受影响子集及：

```bash
uv run python -m pytest -q
npm run check
npm run test:viewer
uv run python scripts/check_docs.py
```

新增 workspace 稳定后再启用并记录 ruff、mypy、contracts、Playwright 和分包命令；命令尚不存在时不得
伪报成功，也不得为了让总数变绿而永久 skip 大模型测试。

### 0.3 最低发布验收

- 干净用户环境可以安装并运行 `virea`；
- machine doctor 能解释当前平台可用/不可用能力；
- 两个依赖冲突的 test-only model 可并存；
- test-only Worker 只验证控制面边界；发布模型必须另有真实 checkpoint 全链；
- 模型 crash/OOM/cancel 不影响控制面；
- canonical211 v3 读取、Viewer 播放和旧 hash/replay 回归通过；
- Motion IR、ModelResult、VrmMotionResult 版本化并持久化；
- VRM body22/humanoid52/full55 profile 可验证；
- Viewer 不做 dataset/model-specific pose repair；
- 多模型安装可恢复，已安装模型可离线二次启动；
- 首次 TUI/Web、catalog、install queue、playground、Viewer、job history 和 diagnostics 可用；
- 每个发布模型的代码、权重、数据/body model 许可事实和功能限制可见；
- 发布声明不包含未实际验证的平台、模型或可商用性。

若 0.3.x 宣称 `avatar_research` 产品 bundle，则 SentiAvatar 的 body/hands/face、stream、非商业许可和
真实样本回归也必须进入该版本验收；否则保持后续 0.3.x 工作包，不阻塞 MoMask 核心发布。

## 安全、隐私与知识产权

- 新路径取消的是 SHA/检查矩阵/安全码运行门禁，不是取消不可信输入、路径、pickle、token、隐私或许可
  边界。
- 控制面不得加载不可信 pickle；遗留 checkpoint 只在模型 Worker 自己的隔离进程中按插件声明处理。
- Worker 只访问声明的模型目录、job staging、输出目录和所需设备；日志不记录 token、原始音频、prompt
  全文或用户绝对路径。
- gated repository、非商业权重、SMPL/SMPL-X/MANO/FLAME 和数据集许可由用户事实与 consent 流程
  处理；确认不等于 VIREA 取得再分发权。
- 根仓库代码许可证仍由 Owner 单独决定；本 RFC 不选择或推断许可证。
- 默认只支持本地 loopback；任何公网模式、外部认证或多租户能力必须另开 RFC。

## 可观测性

每个 job/installation/worker 记录生成式 ID、模型/插件版本、runtime spec、阶段、开始/结束时间、实际
命令、资源、退出状态、错误码和测试证据。日志默认脱敏。可观测性用于诊断与性能分析，不作为新增
SHA、安全码或全矩阵门禁。

## 风险与缓解

| 风险 | 缓解 |
|---|---|
| 上游依赖互相冲突 | 每模型独立 runtime；test-only dependency-conflict integration test |
| 模型输出语义含糊 | 显式 Skeleton/RepresentationProfile；managed path 禁止 shape 猜测 |
| 无摘要后无法证明字节级身份 | 记录 source/revision/file/size/runtime spec 与实际真实 checkpoint 推理/production acceptance；不宣称 bitwise content identity |
| 旧 canonical 回归 | characterization、legacy Reader、bridge 与旧 hash/replay compatibility tests |
| Worker 崩溃或 OOM | 独立进程、Supervisor、稳定 job error、backoff 和资源 admission |
| 许可阻止分发 | license facts、consent、bundle 分类；权重不随核心默认发布 |
| 一次性重写长期不可用 | 小切片 PR、双路径、compatibility shim、每阶段可运行出口 |
| UI 与后端按模型分叉 | schema-driven form、ModelResult/Motion IR 契约、Viewer 零数学修正 |
| 平台声明超过实测 | 未实测标 unverified；发布说明只列真实或受控硬件结果 |

## Alternatives Considered

### A. 保持当前数据预览工具，不增加生成模型

无法满足多模型 motion generation、首次运行和统一模型管理目标，拒绝。

### B. 将所有模型安装进根 Python 环境

依赖冲突和崩溃会扩散到核心，跨平台维护不可持续，拒绝。

### C. 每个模型独立仓库或完整远端微服务

隔离清晰，但会拆散 Motion IR、retarget、Viewer、schema 和兼容测试；0.3 仍以本地单仓库为主，拒绝
作为默认方案。

### D. 一次性删除旧实现并按蓝图重写

无法证明数学和 artifact 兼容，也会覆盖当前 hand solver 与真实模型工作，拒绝。

### E. 所有新资源继续采用 SHA 内容寻址和安全码门禁

与 2026-08-20 用户裁决及新路径性能边界冲突，拒绝。旧 canonical v3 的既有 hash 契约保持兼容。

### F. 继续只使用固定 211D 作为所有模型统一表示

不能表达 face、gaze、contact、object、stream 和 multi-actor；保留为兼容 view，不作为新 IR，拒绝。

### G. Viewer 按模型或数据集修正姿态

破坏单一动作 authority 和可移植性，与现有 Accepted 边界冲突，拒绝。

## Rollout

1. 合并 RFC-0003/ADR-0003 和 WP00 baseline；
2. 锁定命名表与契约 examples；
3. 以 test-only deterministic Worker 完成 state/runtime/model pool/supervisor 的协议边界；
4. 建 Motion IR/canonical bridge 并提取 retarget；
5. 完成 MoMask API/Viewer vertical slice；
6. 完成首次 TUI/Web；
7. 完成 SentiAvatar，再并行 MDM/EMAGE/MotionLCM；
8. 完成 export、第二批模型、目标平台证据和 0.3 acceptance；
9. 每个阶段只有实际 acceptance 通过后才进入下一依赖阶段；并行工作不得绕过共同契约。
