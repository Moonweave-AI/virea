# 在 VRChat 中运行独立 AI

[English](vrchat-operations.en.md) · [架构与部署参考](vrchat.zh-CN.md) · [验收记录](../quality/vrchat-recordings.md)

这份指南针对 Windows 上的两个客户端：你的账号在桌面模式中观察，AI 专用账号在软件模拟的 VR 模式中表演。无需实体头显或手柄。MotionCraft 默认生成动作，SynTalker 可在对话中切换。身体、手腕和手指来自模型；VRChat 再用自己的 IK 求出角色姿态，因此不能宣称逐骨骼完全一致。

## 首次准备

从[仓库安装指南](../getting-started.zh-CN.md)开始，完成[虚拟设备、角色与模型服务部署](vrchat.zh-CN.md)。Unity 角色工程保存在 `.virea-runtime/vrchat/unity/avatar/`；配置、驱动构建、日志和录像分别保存在同级子目录。该目录被 Git 忽略。Unity Editor 和 Steam 的安装路径可在 E 盘；不要把它们复制进 Git。

上传后的 AI 角色才可被另一账号看到；SDK 本地测试角色仅对本人可见。AI 账号需要符合 VRChat 上传权限。账号登录、Unity 许可证、SDK 登录、角色上传是不同步骤。

按 [client-launch.example.json](../../integrations/vrchat/client-launch.example.json) 创建 `VIREA_HOME/config/vrchat-clients.json`，填写安装路径和两个实际账号 ID。示例配置不是密码存储。`VIREA_HOME` 在本机位于 `.virea-runtime/vrchat/home/`。

| 角色 | Profile | 模式 | OSC 输入 / 输出 |
|---|---:|---|---|
| 观察者 | 0 | 桌面 | 9000 / 9001 |
| AI | 1 | 软件 VR | 19000 / 19001 |

这是本机验收配置；底层未配置的 AI 启动脚本默认 Profile 2、19010/19011。页面、启动配置和游戏命令必须一致。Profile 只隔离配置，不代表已登录正确账号。

## 每次开机后的启动

在仓库根目录运行以下命令，启动或复用本地 `stack.json` 中的服务。语言、语音、MotionCraft、SynTalker 和 API 全部就绪后再进入页面。

```powershell
# 启动配置好的本地服务；复用身份与健康检查通过的现有进程。
./scripts/vrchat/start.ps1
# 只检查服务，不启动进程。
./scripts/vrchat/start.ps1 -CheckOnly
```

打开 `http://127.0.0.1:18001/app/vrchat.html`，分别点击观察者和 AI 的启动按钮。AI 启动链包括 SteamVR 与已注册的 VIREA 虚拟设备。按钮复用正确的现有进程；单端重启仅操作对应窗口。游戏恢复自己的有效登录会话；出现登录或验证页时，应在对应窗口完成认证，不能把“进程存在”当作“已登录”。

保持两个窗口未最小化。右上角双视角面板显示真实窗口：上面是观察者，下面是 AI；关闭面板只停止画面采集，后台对话仍继续。

## 同房间与自动全身校准

先核对账号，再让观察者加入 AI 的实例。私有实例必须有有效邀请；两个账号都在线或知道实例编号，不等于有进入权限。**同房间**优先移动观察者，尽量保留 AI 的镜前位置。只有两个当前客户端都确认到达相同的完整实例，状态才显示成功。

```powershell
# 自动选择有入房管道的客户端；优先让观察者加入 AI。
./scripts/vrchat/setup_session.ps1 -Action join -Target auto
# 原地完成全身校准，等待游戏反馈；不会行走、跳跃或改变身体朝向。
./scripts/vrchat/setup_session.ps1 -Action calibrate
# 只读取校准与房间状态。
./scripts/vrchat/setup_session.ps1 -Action status
```

邀请有两种受支持来源：当前游戏实际收到的匹配邀请，或后台显式配置的独立 API 会话。通过 `invite` 发送邀请需要后者；`join/accept` 可使用游戏实际收到的匹配邀请，缺少该证据时，其 API 回退路径才需要相应的后台会话。仅登录游戏不会替后台提供认证。详见[房间接口](vrchat.en.md#automated-session-setup)。不要将密码或 Cookie 写入命令、README 或提交。

连接并绑定 AI 角色后会自动尝试校准，也可以点击 AI 画面下的**自动校准**。本地显示百分比、`[当前步骤/8]` 和错误；进度按实际完成的里程碑计算。100% 要求新的 `TrackingType=6` 回传和完整设备回执。校准结束平滑恢复自然站姿，开始模型播放时交出姿态控制。失败时先检查下方具体原因，再重试；不要在校准途中接管或移动角色。

## 静音交互与模型切换

公共区域保持 Windows 所有活动播放设备静音，关闭桥接音频，开启 AI 和观察者的字幕输出。静音模式仍生成 TTS 来确定语音片段长度，但不打开播放流。录制文件没有音轨。虚拟声卡并非静音演示的前提。

输入一项任务，等待“构思、生成、播放、完成”。用户消息进入观察者原生聊天框；AI 回复按语音时间轴进入 AI 原生聊天框。前端文字或录像附加字幕不能替代游戏内字幕验收。先做一次简短交互，确认另一账号能看到新生成的动作和字幕。

动作可有多段，使用简短英文动作提示；语音可在动作中途开始，也可先于动作结束。动作时长不会被语音 EOF 截短。模型规划产生的语音重叠会按实测 TTS 时长顺延；显式严格时间轴仍拒绝重叠。模型采样遇到 180° 手指旋转歧义时，自动计划保留同一动作计划与 TTS，用记录的新种子重新生成一次；约束检查保持不变，重试仍失败就停止，显式指定种子的任务不会静默重试。

顶部方法选择器可切换 MotionCraft / SynTalker，保留会话和历史；切换会停止旧任务并采用新设置。正常完成、中断和下一轮交接保留已发送的位置与朝向；不会自动回到校准原点。手动接管、重新校准和 AI 入房会重新建立姿态上下文。`generated_vr` 拒绝预设动画和粗略手势映射。

## 直接在 AI 画面中操作

点击**接管 AI**，在可见游戏菜单上完成射线对齐后操作。鼠标瞄准控制器；右键拖动控制观察方向，两者独立。窗口或 FOV 改变后使用**对齐准星**。**放大**仅扩大网页画面，不切换系统全屏。

| 输入（AI 画面获得焦点时） | 功能 |
|---|---|
| 鼠标移动 / 左键按住、释放 | 右手射线 / 扳机 |
| 右键拖动 / 方向键 | 头部观察方向 |
| WASD、Shift、空格 | 移动、跑、跳 |
| Q / Esc、反引号、M、B、Backspace | 左快捷菜单、右快捷菜单、主菜单、动作菜单、返回 |
| E / G、F / H | 右手抓取 / 放下、左手抓取 / 放下 |
| Z / C、左 / 右方括号 | 连续转身、分段转身 |
| 滚轮、Shift + 滚轮、Ctrl + 滚轮 | 纵向滚动、横向滚动、持物远近 |
| 主键盘 0 / 1 / 2 | 小键盘控制头 / 左手 / 右手 |
| 小键盘 4/6、8/2、+/− | 头模式：左右看、上下看、升降；手模式：左右、前后、升降 |
| 小键盘 7/9、1/3、÷/× | 头模式：横移、前后；手模式：偏航、俯仰、滚转 |
| Enter / 小键盘 Enter 或 0 | 当前手扳机；校准姿态中为双扳机确认 |
| R / 小键盘 5、小键盘小数点 | 当前目标复位、全部偏移复位 |
| T、Home、F8 | 手动校准姿态、SteamVR 面板、结束接管 |

抓取、移动和物体交互受当前世界限制。SteamVR 面板不包含在 VRChat 窗口采集中。失焦会释放按键；失联会自动结束接管。绿色准星是驱动确认的请求位置，不是游戏命中证明；以游戏按钮的真实高亮为准。完整原理见[双视角参考](vrchat-views.md)。

## 按症状恢复

| 症状 | 检查和恢复 |
|---|---|
| 场景在线但 API 401 | 区分房间连接与 API 认证；检查系统代理是否切换出口。当前机器已为两个 API 域名持久直连，详见[网络复验](../quality/vrchat-recordings.md#network-session-investigation-2026-10-11)。真实认证过期只处理受影响账号。 |
| 无权进入私有房间 | 获取来自当前房主、发给当前账号的有效邀请。短码不能授予权限。不要靠重启或改写实例后缀绕过权限。 |
| 没有入房管道 | 使用 `Target=auto`；显式指定的不可用客户端不会偷偷改投另一账号。 |
| 平台不兼容 | 核对实际世界支持的平台、当前实例与所选客户端；不要把所有拒绝都解释成认证错误。 |
| 前端回复、游戏不动 | 看模型任务、姿态回执、`VRMode=1`、`TrackingType=6`、AI 身份及校准错误；驱动收到帧不代表游戏已渲染。 |
| `ServerTimeout` 后游戏重连 | 等待两端新的同房间到达记录；若全身追踪降为 3，重新运行原地自动校准，等到 100% / 8 步完成。保存的模型末帧不能绕过追踪就绪检查。 |
| 画面空白或冻结 | 恢复最小化窗口，核对对应 Profile/OSC 端口；陈旧帧不会显示为实时成功。 |
| 鼠标与激光不一致 | 打开可见菜单，重新对齐准星，等待按钮高亮后点击；不要用头部转动替代手柄瞄准。 |
| `manual control expired` | 结束接管并重新获取，检查页面焦点与连接；关闭面板会释放控制。 |

## 录制、停止与证据

按[四条 Demo 的录制与验收流程](../quality/vrchat-recordings.md#recording-procedure)操作。先确认双方全身和原生字幕可见，再连续录制；生成等待保留，禁止剪掉失败后仍称全程通过。发布前检查全片解码、无音轨、四轮完成、真实模型帧、无预设动作、可见字幕和视频哈希。

暂停冻结表演时钟；中断取消当前任务并保留末帧。结束接管释放人工输入；断开桥接停止输出。关闭网页不是停止后台服务。需要停止服务时使用当前部署的进程管理方式，保留另一个游戏客户端；不要批量结束所有 Python、Steam 或 VRChat 进程。
