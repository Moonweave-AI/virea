# 保留持续运动意图，去除冗余身体阶段

## 问题与证据

本轮针对“LLM 反复规划站立，ARDY 实际没有充分运动”。修改前先保存了用户页面的舞蹈、华尔兹、行走执行记录。
其中华尔兹被规划成 4.4 秒舞步、3.6 秒恢复站立，随后还有 2 秒末尾恢复；另一轮转身计划把说话前和说话后的站立都列成独立身体目标。
这不是 ARDY 每生成一窗就必须停下，而是上游交给它的任务已经包含了大量静止条件。

进一步的真实模型探针发现三个相互独立的问题：

- 审查只选发言，所有初始身体目标均被视为必须覆盖，冗余站姿无法被审查删除。
- 多层 LLM 重写同一目标会丢失语义；一次审查将明确的转身目标改成说话时双手托腮。
- `continuation_description` 是另一段独立生成的条件，可能描述收势；长动作的后续窗口因此提前改做终态。

## 原始资料与采用范围

在前一轮 [事件编排研究](appropriate-timing.zh-CN.md#原始资料与阅读范围) 的基础上，重新阅读了 [ARDY 论文](https://research.nvidia.com/labs/sil/projects/ardy/assets/ardy_paper.pdf) 的方法与 §3.4，以及官方 [`scripts/generate.py`](https://github.com/nv-tlabs/ardy/blob/main/scripts/generate.py) 的自回归循环。官方实现持续向模型提供运动历史和文本条件，并按训练上下文范围截取历史；推理窗口不是新的身体任务。

[官方项目说明](https://research.nvidia.com/labs/sil/projects/ardy/)和[交互演示文档](https://github.com/nv-tlabs/ardy#interactive-demo)区分在线文本更新、历史长度、未播放缓冲和未来约束。这支持“任务条件改变才更换运动条件”的实现方式，没有支持在每个窗口增加站立准备或恢复。这里只借鉴模型调用与职责边界，不把论文中的速度、自然度或物理控制能力当成本项目的测量结果。

## 职责与数据契约

1. 意图 LLM 同时给出 `goal`（持续执行什么）和 `completion`（什么可观察结果表示任务完成），并生成口头正文。完成条件与持续运动描述分开存储。
2. 审查 LLM 为每个候选目标分配语义归属：独立活动、随声表达、背景状态、最终恢复或被其他活动覆盖；同时选定实际发言和事件依赖。必需的逐索引决策确保每个候选都有归属，不靠动作关键词过滤。
3. 保留目标的内容、完成条件、场景实体来自原始意图。审查只能选择目标和调整时机，不能再次改写动作内容。若原始目标不足以完成用户任务，审查反馈差异，由意图层修订整个候选。
4. 新计划由每个已审查活动对应一个持续运动条件；不同运动条件在意图序列中明确表达。运动编译器选择执行器、简短英文描述、预算及整项活动需要的最终恢复，不再另增一组准备／等待阶段。描述由 LLM 将活动展开为必要的可观察身体运动，单独的情绪、风格形容词不足以表达运动。旧计划仍可读取。
5. 同一活动的首窗和后续窗口共享该描述，实际身体历史继续传递；不再要求 LLM 另写入口和延续条件。最终恢复只属于整项活动结束。
6. 删除目标时，保留发言若引用该目标，LLM 必须给出真实替代事件。程序重绑原始索引，拒绝缺失引用和循环；不会猜测删除目标后应当立刻发言还是等待活动结束。

静态表演和真实的起立仍是合法活动。代码不按“站立”“舞蹈”等词分类，不预设某个请求应使用哪个模型或多少秒。LLM 决定任务归属与执行器，程序只约束结构完整性和职责边界。

`objective_review` 随采纳的 appraisal 进入现有执行链，包含用户所需结果、保留目标和省略理由；静默活动也走同一审查路径。事件修订先在原候选上进行，避免为了修复索引而重复生成有效台词。

## 验证与复现

自动回归覆盖：原始索引在语音／动作两侧的一致重绑、删去背景任务、明确静态表演保留、起立保留、语义内容不可被审查覆盖、静默计划、事件别名循环、删除全部非发声内容、局部依赖修订，以及 0/2/6.4/12.8 秒取窗时持续描述不变。角色后端 184 项测试通过，修改文件 Ruff 检查通过。

扩展回归 `tests/refactor tests/characterization` 为 625 项通过、4 项跳过、1 项失败。失败是已有的 API 路由枚举测试：预期清单未包含当前已存在的角色偏好、自然姿态、身体回执等接口；这些接口及该测试与修改前 HEAD 一致。生成文档的 5 项测试通过。没有将这些结果合并表述为全库通过。

真实模型使用现有长角色设定与 Qwen3.5-9B Q4_K_M，调用本机 ARDY。运行：

```powershell
.venv/Scripts/python.exe scripts/character/benchmarks/evaluate_body_objectives.py `
  --config configs/character/rtx5090.json --home $env:VIREA_HOME `
  --cases tests/fixtures/character/body-objectives.json `
  --output (Join-Path $env:VIREA_HOME 'evidence/body-objectives') --motion
```

可通过 `--persona` 指向本地角色设定；不将私人角色文件提交到仓库。探针保存每层的结构化输出、最终计划、原生动作和运动幅度；不会保存隐藏推理内容。运动幅度只能排除完全静止，不能替代动作语义、接触质量或审美评价。

本轮原始证据保存在仓库外 `VIREA-Data/evidence/motion-intent-20260930/`。探索目录记录了失败方案，不应把任何一个名字含 `final` 的中间目录当作通过证明。提高推理预算未稳定改善规划；将完成状态直接用作持续动作条件还使长舞蹈变成全程收势。这两种方案都未采用。

最新探针 `immutable-intent/waltz.json` 保留一个 8 秒旋转踏步活动，另规划一次 2 秒最终恢复；4 个原生生成窗口使用完全相同的持续运动条件。原生轨迹累计约 0.331 米，髋关节累计旋转约 76.9 度。这证明该样本没有被拆成反复站立阶段，但不足以认定它达到了专业华尔兹动作质量。

同批十二秒舞蹈原生测试有 6 个窗口，累计根轨迹约 2.66 米；静态表演和蹲下后起立都保留了原本任务。完整六案例中，转身案例在共享 GPU 下超时，其他五项完成规划与原生调用；普通聊天仍被 LLM 选为一个较长的安慰姿态，不能评价为所有语义判断都已正确。

### 从原生输出继续检查实际页面

第一次 Miku 页面复测 `browser-dance.json` 的实际时段为 6.4 秒活动、5.6 秒同一活动、2 秒最终恢复，没有中途站立任务和语音；但导出的运动轨迹显示舞蹈期间仅约 0.14 米移动。这揭示了单看阶段数量或从中性姿态开始的探针不足以证明页面表现。

随后从录制提取相同入口姿态，用合成的静止历史控制初态，分别改变历史长度与文本条件：

- 缩短到 8 帧历史有时提升响应，但 3 次重复中仍有幅度较小的样本，另有一个样本最大单帧关节旋转约 119 度；未因此修改共享配置或原生历史实现。
- “活泼、有节奏”的抽象描述与具体步法／肢体描述产生明显差异。具体描述的对照测试有更大的持续运动，但不是固定随机种子的成对统计实验。
- 运动编译 LLM 的契约改为一句简短的可观察运动描述，由它决定相关细节；没有把实验中的舞蹈字符串写进产品路由或自动替换。过度详细的早期版本曾超出原契约的 320 字符限制，未被视为通过样本。
- 最终编译复测 `concise-speak-turn-speak.json`、`concise-waltz.json`、`concise-long-dance.json` 均通过结构校验，分别保留一个转身、旋转踏步、十二秒摆臂轻跳活动。舞蹈的 LLM 原文直接进入 ARDY，在上述同一入口姿态和 40 帧静止历史下重复两次，累计轨迹约 2.40 米、3.86 米。统计保存在 `concise-dance-native-metrics.json`。

原生轨迹更大并不自动等于自然、无穿插或优美；页面实播、任务语义和终态还需分别检查。没有将这次修复解释为训练了更好的运动模型。

最终页面复测 `browser-dance-final.json` 使用现有 Miku、原角色设定与页面当前声线。LLM 采纳单个十二秒活动，实际播放 6.4 秒和 5.6 秒连续窗口，之后一次 2 秒恢复，任务状态为 `completed`，没有执行错误。七个活动生成包合计根轨迹约 5.14 米；末尾检查 `supported=true`、`settled=true`，root speed 约 0.026 m/s。实际回放可见跳步与身体转向，截图 `vrm-dance-final-2s.png` 和 `vrm-dance-final.png` 分别位于约 2.2 秒、9.9 秒。请求到意图采纳约 24.34 秒，再到运动编译完成约 10.41 秒；这仍有明显规划延迟，不能称作低延迟交互。该次回合静默，不能用它证明语音自然度。

附加的“先说心情、安静转身、再说告别”页面验证没有达到完整语义验收。第一次语言服务返回输出格式解析 500；再次执行只有一个 3.6 秒转身和一次 2 秒恢复，第二个发声条目确实在 `objective:0:end` 后释放，但正文错误地保留了“（转身）”而遗漏告别，开始条件也误写成 `utterance_start`。动作实际上晚于第一句，是编译延迟造成的，不证明该依赖正确。原始记录为 `browser-speak-turn-speak.json` 和 `browser-speak-turn-speak-retry.json`。这暴露的是 LLM 语义审查仍会误判，不能靠结构和时段回执宣称问题已全部解决。

对上述失败候选作审查对照：只提供当前请求时，原版和去掉候选自述目标的版本都能发现缺少告别；加入会话与身体任务上下文后，改成普通对话历史或仅背景历史均漏判。证据为 `review-executable-probe.json`、`review-history-probe.json`。没有据此加入动作词表、台词替换或未经证明有效的历史裁剪；此类上下文敏感的语义遗漏仍是后续模型质量评测项。

该批测试与用户游戏共享 GPU，显存约 23.7/24 GB；已出现模型请求超时，耗时不用于空载性能结论。概率模型仍可能漏判活动意义，少量测试不构成所有请求无冗余阶段的保证。
