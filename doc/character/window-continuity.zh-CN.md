# 动作窗口连续播放

## 原因与修复

- `BehaviorPlayer` 原来在每个身体时段末尾等待 completed 回执，再等下一段 playing 回执；即使运动已经预取完成，网络往返仍使人物保持末帧。现在回执进入同一顺序队列，捕获事件发生时的身体状态和音频时钟；准备好的后继直接播放。下一次规划仍等待 playing 被后台接收，维护预订依赖。
- `SpatialPlayer.run` 原来在每次 HTTP 预订之间清掉相邻帧、重新开始计时。现在缓存立即后继的首窗，用其真实帧计算末端导数；接续时保留上一末窗和预定边界时刻，继承 RAF 越过边界的时间，不把它重新归零。打断、模型切换和回放会清掉此关联。
- 渲染和异步队列推进有各自的 RAF 回调。现在渲染直接根据当前时钟找到正确的已缓存原生窗，避免队列推进稍晚时重复显示旧窗末帧。一次长帧也会越过所有已经走完的窗口。
- 明确的用户时间预算已经结束时，再调用 LLM 判断不能改变该预算，只会延误收势；执行层因此直接投影已有预算，提前生成恢复。无明确预算时保留执行 LLM 的完成判断。预测仍不会提交完成状态或提前释放后续发言条件。
- 跨模型约束窗保留自己的显式开始时刻；继承时钟越界量不会快进跳过尚未到达的桥接段。
- 已终止活动残留的 `finish_requested` 原来会拒绝后续无关的 SentiAvatar 预订，触发反复规划。现在只取消仍推进旧活动或等待旧活动结束的预订，允许终止后的伴随表达；后台复用检查与前端有效性检查保持一致。回执被拒绝会显式报错，不会沿着已经失败的回执队列无限重试。

同帧仍只有一个身体源；没有新增固定站姿、关键词动作路由、动作时长猜测，也没有用拉伸播放速度掩盖生成不足。后继真正来迟时从该段开头恢复，不跳过尚未展示的动作。网络回执失败会取消渲染并报错；旧请求迟到的失败不能停止新播放。

## 验证

自动化覆盖：延迟回执下无播放间隙、后台回执顺序与观察时刻、异步失败取消、旧失败隔离、窗口边界位置/角速度、RAF 调用顺序、迟到数据、取消、回放及明确预算的投影与提交。另运行前端全量与角色后端回归及生产构建。

真实测试使用本机 RTX 5090、现有 Qwen/ARDY/SentiAvatar/Kokoro 服务和 `miku.vrm`，保留用户角色设定与 `zf_040` 声线。证据目录：`<DATA_ROOT>/evidence/window-continuity-20261002`。

并行讲话/挥手（`browser-speech-motion.json`）：3 个 PCM 窗口连续播放；两个 ARDY 主窗和恢复窗约在 +2.73、9.13、15.53 秒开始，0 执行错误。动作结束由执行 LLM 判断，没有套用舞蹈测试中的时间预算。录制仍包含起始阶段等待语音可用的时间。

最终构建再测讲话/挥手（`browser-wave-latest.json`）：4 个 PCM 窗口连续播放，ARDY 主窗与恢复窗分别在 +2.657225 和 +9.061782 秒开始，相差 6.404557 秒（主窗内容 6.4 秒），0 执行错误。

同会话下一轮普通聊天（`browser-chat-latest.json`）：SentiAvatar 三个窗口均在播放前就绪，0 过期、0 执行错误；身体时段在 +0.068824、+2.426843、+7.218711 秒开始，声音在 +0、+2.4、+7.2 秒开始，最终完成手势回收。此处语音始终沿自己的音频时钟继续，预订时长也按剩余音频更新，不能把时段起点差直接当成语音空档。

同会话第三轮明确要求停止旧活动后继续中文聊天（`browser-stopped-chat.json`）：确认终态 `completed`、`finish_requested=true`，后续 SentiAvatar 预订均正常完成；4/4 表达窗口及时就绪，0 过期、0 执行错误。ARDY 恢复后约等待 2.10 秒才到显式约束桥的开始时刻，桥后正常交接 SentiAvatar；此例验证保留计划时机，不应计为所有跨模型等待均被消除。总录制 15.87 秒。页面截图 `studio-final.png`。

回归结果：前端 133 项、后端角色 232 项通过，Ruff、TypeScript 和 Vite 构建通过。保留既有 viewer 大 chunk 提示。GitNexus 已刷新并执行 `detect_changes(scope=all)`，覆盖 11 个变更文件，未返回 partial/truncated；其风险为 critical。索引的空符号 ID 会混合部分函数调用链，因此同时人工核对预订、播放、取消与回放调用点；不把图中的空调用集当作无影响。

额外负例保留：完整故事请求触发既有 Qwen 结构化规划未正常结束（`browser-story-planning-failure.json`），约 106.65 秒后失败，尚未产生动作；此问题不属于播放器窗口衔接，不能声称本次已解决。旧版本跨轮次失败的服务器完整快照在 `session-chat-before-receipt-fix.json`；同名浏览器导出的旧文件受文本工具长度限制截断，不用于统计。

这些修复解决播放器人为插入的窗口停顿，不保证模型原始运动本身处处自然。执行 LLM、动作推理或资源争用超过缓冲时仍可能出现真实等待；跨模型末端约束尚未就绪时的调度也与同模型连续窗不同。
