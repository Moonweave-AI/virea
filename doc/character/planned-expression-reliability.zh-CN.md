# 连续表达的交付与收尾

这次以用户提供的 Miku VRM 和现有角色设定复测。问题不是单一的“动作模型不够快”：模型进程被回收、生成窗口迟到、错误的身体承诺、字幕范围和收势生命周期叠加，造成了大量保持姿态与突兀收尾。用户的原始会话、人设、模型文件和逐帧证据保存在仓库外，没有提交。

## 已复现的因果链

| 现象 | 证据与原因 | 修正 |
| --- | --- | --- |
| 语音大半播完才出现动作 | 一次可选动作在 NORMALIZING 阶段被丢弃；该状态未进入 drain 分支，取消动作意外杀掉驻留 worker。下一轮重新加载模型 | 推理完成后的规范化、重定向、验证、导出都可排空并丢弃结果；不把过期结果发布给前端，也不重载健康模型 |
| 长回复中途再度断档 | Miku 实测前三窗正常，第四窗报 INFILL_OUTPUT_INVALID，下一窗冷启动约 31.3 秒 | 插帧器按 RVQ 层限定候选词表，排除其他码本和 MASK；保持原六次置信度排序与固定关键帧。不是对非法结果取模或截断 |
| 开头长时间保持姿态 | 旧实现立即发布语音，SentiAvatar 作为异步附件，没有初始呈现余量 | 增加一次性的、有上限的初始准备预算，默认 1.8 秒；后续窗口提前生成。预算耗尽后语音独立前进，不逐窗额外等待 |
| 普通聊天被编排为悬空坐姿 | 对话尚未理解就要求填写 resting；场景“用户位置”被当作坐下的支撑目标 | 移除强制 resting 输出；目标携带动作能力，sit 只能绑定可坐支撑点，move_to 绑定站位。模型任务也做服务端复验 |
| 每轮末尾另来一次 ARDY | 语音完成时自动创建新的收势身体任务，覆盖已完成活动的含义 | 真实空间活动保留自己的模型收势；纯交际手势结束后只做一次姿态连续的回收，恢复此前的上下文支撑姿态，保留平面位置 |
| 记录看起来反复说同一句 | PCM 重分窗后，每个字幕仍复用了完整上游句子；音频样本本身没有重复 | 字幕按同一窗口消耗的文本切片。此切片是时长比例近似，不宣称逐字强制对齐 |
| 语音结束后大量极短预订 | AudioBufferSource 对象仍存在，但音频时间已结束，调度器仍报 available | 按输出音频时钟判断有效性；服务端拒绝把零剩余时间当成 SentiAvatar 可用窗口；新窗口不能沿用过期动作的 ready 标记 |
| ARDY 后再说话，头、手和脚突然抽动 | 首个语音窗口内记录到头部约 20° 单帧跳变；检查原始 VRMA，各躯干轨道相邻 50 ms 变化小于 1°，头轨道恒定。Three.js PropertyMixer 会跳过未变化的属性写入，而捕获前恢复固定入场姿态，破坏了该缓存假设 | 每次恢复上次未经过渡修正的源采样；新片段单独建立源状态。恒定轨道不会退回 ARDY 姿态，可见姿态也不会反馈进源动画。用真实 AnimationMixer 复现，旧代码产生 143.87 rad/s，新代码通过连续性断言 |
| 不均匀帧率放大过渡速度 | 采样与渲染分属两个 RAF，过渡时间在绘制之后累加，可能把上一帧的时间变化挤到下一帧 | 在同一渲染回调先采样，再交接，再呈现；过渡采用当前帧时间增量。用 100 ms 单帧与 25 个 4 ms 帧验证相同时间的姿态一致 |
| 明确要求十二秒却没有身体任务 | 模型给出 duration_seconds=12，却漏填 duration_evidence，编译器正确拒绝了不完整计划 | JSON Schema 将时长和原文依据约束为成对的分支，保留字段说明和原文校验；数值边界错误允许一次有界修复，不执行无效计划，也不会为错误计划猜一个时长 |

另修正了结构化对话请求中历史被同时放入 messages 和 previous_turns 的重复传入。GitNexus 显示该函数有 6 个直接调用者、13 个上游受影响符号，风险 MEDIUM；插帧器及其生成入口为 HIGH。改动按这些路径分别验证。

## 执行契约

对话层先决定是否采纳身体目标。普通讲述产生一个连续语言流和分窗语音，不把故事里的人物动作直接变成角色的空间任务。身体编译层只处理已采纳目标，活动拥有自己的结束语义。

SentiAvatar 和 ARDY 按时间段独占全身，语音和面部继续沿统一输出时钟播放。初始 1.8 秒预算属于呈现准备，不改变音频或模型时间尺度；一旦开始，不为迟到的动作倒带。窗口切换保留实际姿态和速度，中间不回收；结束交际表达时才恢复此前的支撑姿态。该姿态可以来自已经完成的坐姿等活动，绝非导入 VRM 的 T pose。

执行链仅显示公开执行事实：当前轮次、身体预订、语音窗口、生成各阶段耗时、是否复用 worker、是否应用连续历史、过期结果和实际驱动。头部峰值附带播放时刻、模型、语音包、帧间隔以及变化最大的关节旋转，便于区分源动作与呈现问题。完整导出仍保留会话事件，主画面不再把前一轮已结束的任务显示为本轮动作序列。

## 已完成的真实测试

环境为 RTX 5090 Laptop 24 GB、已有 Qwen 9B Q4、CUDA Kokoro、SentiAvatar 与 ARDY，角色为用户提供的 Miku。以下是单机样本，不是统计基准。

- 原失败输入 `INFILL_OUTPUT_INVALID` 用相同请求参数回放后成功通过推理、重定向和导出。此回放走普通 Job API，包含一次冷启动，耗时约 29.45 秒，不能计作常驻推理延迟。
- 修复后长对话：57.425 秒音频，13/13 动作窗口及时交付、0 过期、0 动作错误、13 次复用 worker；除首窗外均携带连续历史。各窗端到端动作生成约 0.86–1.78 秒，累计 RTF 0.283。语音起点连续，没有音频拼接空隙。
- 同一长对话录制 59.005 秒，末段语音后约 1.58 秒完成面部释放和手势回收；没有额外 ARDY 身体任务。最终头部/关节速度为 0，脚底间距接近 0，目视为双臂自然垂下的站姿。
- 首段音频生成就绪 9.562 秒，首个联合表达就绪 10.625 秒。当前首响仍受长人设和对话规划影响，不能宣称即时回复。
- 十二秒活动计划的时长契约回放：原漏填依据导致失败；新 schema 返回用户原文依据，并成功编译为 3 个阶段、总计 12 秒。
- 最终版本舞蹈实测：活动阶段 4+4+4 秒，期间 5 个 ARDY 执行窗口均无 settling，只在整个活动之后有一次 4 秒终止收势。2/2 语音动作窗可用，动作生成 1.016/1.125 秒，头部峰值 92.5°/秒。语音 5.55 秒，完整身体录制 19.09 秒：此处是独立的十二秒活动，语音结束后继续完成活动及收势，执行链明确记录来源。
- 同一会话紧接着聊天：2/2 窗可用，动作生成 1.047/1.156 秒，7.475 秒音频，完整录制 9.154 秒，没有新 ARDY 任务。头部峰值 149.2°/秒、对应单帧 0.81°/5.4 ms；最终恢复此前上下文站姿，脚底间距接近 0，关节速度为 0。此前同类交接曾出现 20–29° 的单帧跳变。不同轮次模型输出不同，峰值比较不是配对统计实验；缓存错误另有确定性测试复现。
- 最终构建再测完整中文故事：直接讲完，没有中途再确认；49.275 秒语音、11/11 动作窗口可用、0 错误/过期，动作生成 1.032–1.625 秒。完整录制 51.021 秒，无 ARDY 任务；头部峰值 137.1°/秒，结束后头部和关节速度为 0，目视双臂下垂、双脚落地。字幕窗口覆盖全文，没有重复整句。
- 将三维世界四元数归一化后再计角度，保证测量公式前提；这一步本身没有消除第二轮跳变。实际原因是上面的 PropertyMixer 源缓存错误，不能把归一化当作动作修复证据。

本机证据目录：`D:/AI-Program-Project/VIREA-Data/evidence/planned-expression-20260929/`。保留了修复前失败、修复后执行链、原失败输入回放和 Miku 结束截图。

自动验证：角色与驻留生命周期 126 项、任务取消与进程恢复 39 项通过；Web 119 项通过；SentiAvatar Runtime 22 项及 CPU/CUDA 两个子测试通过；TypeScript/Vite 构建和修改文件 Ruff 检查通过。基础 API 虚拟环境缺少音频与 sklearn 依赖，因此 Runtime 测试在实际 GPU Runtime 中执行。现有 WebGL 依赖打包体积提示仍在。最终 Miku 会话的 9.2 秒完整音画录制也通过 UI 同步回放，正常结束。

## 验证边界

字幕尚未做逐字强制对齐；面部表现受到 VRM 实际表情通道限制。SentiAvatar 的原生连续历史并不等于它能从任意 ARDY 姿态精确续写，跨模型仍由时间段交接处理。当前没有训练新模型、建立动作美感评分器或完成物理交互系统；不能保证任意动作和任意骨架的最终姿态都自然。模型边界、部署异常和呈现异常必须分开记账。
