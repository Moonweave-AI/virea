# 每段动作都回到自然姿态

按用户明确要求，持续角色的每个动作片段都执行完整收势：
**播放动作 → 沿末端速度平滑放松 → 到达自然姿态 → 提交完成回执 → 开始下一段**。
这替代了此前仅在整句最后一个窗口收势的策略。

自然姿态使用角色载入时的放松站姿，保留已执行的地面位置、骨盆朝向和手指形状。
每段通过 0.65–1.6 秒的过渡降低身体速度，解除口型与闭眼残留；下一段从这个实际姿态起步，
不会直接跳到新动画首帧。收势不需要模型推理。

音频、字幕、面部、身体与收势共用播放时钟。该段语音结束后字幕消失，身体继续收势；
下一段语音与动作一起等待前段完成。分段间因此包含有意保留的收势时间，
测量调度空隙时需扣除这段时间，不能继续把完整间隔与旧的 250ms 阈值比较。
暂停冻结整个时钟；主动打断保留当时实际姿态。

后继资源仍可提前生成、加载，但不会提前播放。`continues` 仅表示同一句是否还有后续文本窗口，
不再控制是否收势。每段都不使用上一段收势前的 RVQ 尾码，因为播放层自然姿态无法反向编码为模型历史。
角色 API 将 `native_history` 报告为 `false`，要求该能力的创建请求明确拒绝；
底层模型自身的历史条件能力不被删除。

## 验证方式

`ending_e2e.mjs` 重播三组固定的真实模型资源，将前两段标为非末段，检查每段收势、
自然姿态、前一段终点与下一段入口一致，以及收势中暂停与打断。
`continuous_e2e.mjs` 在正式页面验证真实模型长回复：所有完成回执包含收势时长，
各段不使用旧尾码，扣除收势后的调度空隙仍单独测量。

单元测试覆盖回执前不推进文本历史、所有分段都清除模型历史依赖，以及能力声明与实际行为一致。
数学收势算法、足部 IK 和持续呼吸待机的边界与[此前记录](motion-endings.zh-CN.md)相同。

## 本机结果

RTX 5090 Laptop、Chrome、Seed-san VRM，42 项角色编排测试和 11 项前端动作测试通过，
生产构建与 Ruff 检查通过。[机器可读证据](evidence/segment-rest-20260927.json)保留源码摘要与分项测量。

| 固定真实资源重播 | 是否还有后段 | 收势时间 | 自然身体姿态误差 | 下一段入口与前段终点误差 |
| --- | --- | ---: | ---: | ---: |
| 打招呼 | 是 | 0.91s | 0 rad | 0 rad |
| 解释 | 是 | 1.27s | 0 rad | 0 rad |
| 道别 | 否 | 1.39s | 0 rad | 0 rad |

自然身体误差比较躯干、头颈、肩、手臂、腿与脚的局部四元数；骨盆朝向和手指不要求回到初始值。
入口误差比较完整骨骼姿态，第一段与载入姿态比较；后续段与前段收势终点比较，并检查地面位置不跳变。
收势期间暂停 400ms 时姿态与时钟不变，打断后保留当时姿态。

正式页面的真实长回复生成三个分段，收势分别为 1.29 / 1.20 / 1.24 秒。
两个语音间隔为 1.40 / 1.30 秒，扣除有意保留的收势后，调度空隙均约 104ms；
三个包的 `native_history_applied` 均为 `false`，文本没有丢失或重复。
打断后下一次动作生成用时 2.03 秒。Chrome 在该长回复脚本的退出阶段挂起，
已在完整保存行为断言与观测后停止本次测试进程；固定资源重播脚本正常退出。
